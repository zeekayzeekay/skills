# Delivery calibration probes

These portable synthetic cases exercise decisions, not exact wording. Give a fresh agent the named skill, the selected prompt, and only that prompt's raw artifacts. Keep this rubric out of the evaluator context. Use an exported snapshot or isolated temporary workspace; the prompts authorize no project changes, live calls or publishing. Resolve skill dependencies from the same candidate release.

| Prompt | Expected observable behavior |
|---|---|
| `review-control.md` | Recognizes the supported signed-total/count behavior and existing evidence. Unsupported input types do not become current defects. An additional durable count test may be an iteration, not an automatic blocker. |
| `review-core.md` | Finds the wrong selection on multiple candidates and false known-zero cost when an attempt is unpriced. Both affect current required outcomes despite passing singleton tests. |
| `evidence-gap.md` | Keeps required real matching evidence unvalidated and blocking; does not fabricate a live run or demand unrelated failure matrices. |
| `planning.md` | Keeps a read-only personal CLI small, preserves justified configuration/module boundaries, and avoids a database, principal/space history, tenancy or server without current need. |
| `existing-exposure.md` | Reuses the unchanged local contract for the routine fix. Treats the later public read endpoint as a separate exposure change with focused access requirements and honest mode/promotion status. Parallel AI sessions do not create human-contributor bureaucracy. |
| `fix-triage.md` | Separates the original defect, redundant check and incompatible reviewer requests. Rechecks the correction, seeks resolution of the disputed requirement, and preserves unresolved readiness evidence rather than cycling or claiming a pass. |

The control and planning scenarios preserve the earlier positive smoke cases. Compare them against the prior installed release when available, then run the changed release. The intentionally flawed core fixture is an adversarial case, not application code. The passing fixture tests are part of the evidence supplied to the reviewer, not the acceptance test for this skill update.

Record the agent, skill snapshot, supplied inputs, response and assessment outside Git. These bounded probes support the tested decisions; they do not establish statistical reliability, every harness's invocation behavior, or exhaustive correctness.
